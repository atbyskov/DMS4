1.1 Diagnosis

Three coupled symptoms:

  1. Penalty R saturated at penalty_max = 1e9. The accepted-step update at slp_MVP_advanced.py:793–797 grows R by penalty_increase = 10 whenever violation does not drop by ≥5% in one step. For an FEA-driven problem starting infeasible this fires almost every iteration, so R walks 1e3 → 1e4 → … → 1e9 in roughly six accepted steps.
  2. LP cost vector becomes degenerate. With R = 1e9 and a_F ≈ 50, the merit gradient w.r.t. y is a_F · (R + y) ≈ 5e10, while df is O(1). HiGHS still solves the LP, but every search direction is "minimize slacks at any cost," driven by linearizations the noisy FEA cannot honour.
  3. Trust region collapsed despite the min_dv_box_limit floor. _adaptive_move_limit correctly floors each box at max(2·xtol, move_limit_min) = 2e-4, but the manual shrinks at slp_MVP_advanced.py:640–641, 733–734 are applied after the floor: 
    xLcur = x - (x - xLcur) * backtrack_shrink
xUcur = x + (xUcur - x) * backtrack_shrink
    These bypass the floor. A handful of rejections (10 in this run) multiplies the box width by 0.5k below 1e-5. This is the proximate cause of the termination message.

With R ≤ 1e6, the merit gradient on slacks (a_F·R ≈ 5e7) is still dominant over df but not condition-destroying, so the LP can balance f versus slack reduction.

2.2 Switch to the augmented-Lagrangian variant

The pure merit variant relies on R → ∞ to drive slacks to zero. AL uses multipliers (λ ← max(λ + R·y, 1)) so the slacks shrink at fixed moderate R. The merit becomes

Φ(x, y) = f(x) + a_F · ∑i (yi·λi + ½·R·yi2).

Plumbed through three places:

  • Main_Self_Written_Test.py — new key "algorithm": "al" in Solver_Settings.
  • optimization_self_written.py:36–50 — added "algorithm": Solver_Settings.get("algorithm", "merit") to the slp_options dict that is forwarded to solve_slp_mvp.
  • slp_MVP_advanced.py — no change; the algorithm="al" code path already existed (see merit_val / merit_grad_y and the multiplier update at line 787).

2.3 Enforce min_dv_box_limit after manual shrinks

This is a real bug in slp_MVP_advanced.py: the two manual shrinks (LP-failure branch and rejection branch) divide the box width by 2 without consulting the floor that _adaptive_move_limit maintains. Fixed by introducing a small helper and calling it right after each manual shrink.

New helper

def _enforce_box_floor(
    x: np.ndarray,
    xLcur: np.ndarray,
    xUcur: np.ndarray,
    xLorg: np.ndarray,
    xUorg: np.ndarray,
    min_dv_box_limit: float,
) -> Tuple[np.ndarray, np.ndarray]:
    """Re-impose ``min_dv_box_limit`` after manual trust-region shrinks.

    The backtracking branches multiply ``(xUcur - xLcur)`` by ``backtrack_shrink``
    directly, bypassing the floor that ``_adaptive_move_limit`` keeps.  Without
    this re-clip the trust region can collapse to zero and the solver reports
    "no acceptable step and trust region is below move_limit_min" spuriously.
    """
    if min_dv_box_limit <= 0.0:
        return xLcur, xUcur
    xLcur = xLcur.copy()
    xUcur = xUcur.copy()
    for i in range(x.size):
        width = xUcur[i] - xLcur[i]
        if width >= min_dv_box_limit:
            continue
        deficit = min_dv_box_limit - width
        grow_left  = min(0.5 * deficit, max(0.0, xLcur[i] - xLorg[i]))
        grow_right = min(0.5 * deficit, max(0.0, xUorg[i] - xUcur[i]))
        xLcur[i] -= grow_left
        xUcur[i] += grow_right
        remaining = min_dv_box_limit - (xUcur[i] - xLcur[i])
        if remaining > 0:
            extra_right = min(remaining, max(0.0, xUorg[i] - xUcur[i]))
            xUcur[i] += extra_right
            remaining = min_dv_box_limit - (xUcur[i] - xLcur[i])
        if remaining > 0:
            extra_left = min(remaining, max(0.0, xLcur[i] - xLorg[i]))
            xLcur[i] -= extra_left
        xLcur[i] = max(xLcur[i], xLorg[i])
        xUcur[i] = min(xUcur[i], xUorg[i])
    return xLcur, xUcur

4. What to watch on the next run

  • M column (penalty R) should stay ≤ 1e6 and grow slowly. If it still saturates, the AL multipliers are not catching up — lower penalty_increase further or raise the AL multiplier floor in slp_MVP_advanced.py:787.
  • viol column should trend downward. With AL, this is the multiplier doing the work, not R.
  • If the run still terminates with "trust region is below move_limit_min," it is now a real trust-region collapse (not the floor bug) — likely linearizations too inaccurate at your scale. Try finite_diff_rel_step = 1e-2 or fd_type = "central".
